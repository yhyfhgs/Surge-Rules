# Private device profiles

`tools/device_profiles.py` builds five complete private configurations for manual
distribution. It does not activate Surge, modify Tailscale, change Windows
settings, or publish anything. The existing active files remain independent
until the owner imports an output.

| Output | Intended environment |
|---|---|
| `Surge-Mac.conf` | macOS with a separate Tailscale client |
| `Surge-iOS.conf` | iOS with Surge's native Tailscale outbound |
| `Clash-Windows.yaml` | Windows / Clash Verge Rev with a separate Tailscale client |
| `Clash-Windows-Campus.yaml` | The same Windows setup, physically on the campus network |
| `Surge-Macmini-Campus.conf` | macOS campus gateway with a separate Tailscale client |
| `verge-settings.merge.yaml` | Two application preferences to merge, not a Mihomo subscription |
| `tailscale-dns-off.sh` / `.ps1` | Manually disable Tailscale DNS acceptance on target desktops |

## Sources and updates

Public list order, policies and modifiers still come exclusively from
`config/routing.json`. `lists/` and the generated `clash/` remain the common
routing source. `config/campus-services.json` describes the optional campus
overlay and its evidence; it is not another public list-order table.

The private inventory is stored outside this repository, conventionally at
`../DeviceProfiles/inventory.json`. It has one server address per logical node,
separate Surge/Clash protocol parameters, and one shared member list per group.
Snell and VLESS credentials are not interchangeable. Native iOS Tailscale
identity sections and MITM material stay private. Device bases preserve their
other settings; shared routing/DNS blocks are regenerated. Do not edit generated
files to update nodes: edit the inventory instead.

One-time import (the destination must not exist):

```bash
python3 tools/device_profiles.py init \
  --mac ../Surge.conf --ios ../Surge-iOS.conf \
  --clash ../Clash/Clash.yaml --gateway ../Surge.conf \
  --inventory ../DeviceProfiles/inventory.json
```

The importer refuses disagreement between desktop Surge and Clash node names,
server addresses, and group members. Desktop Surge supplies shared Surge node
definitions, replacing stale mobile definitions.

Before normalizing bases, the importer collects endpoints from all reference
profiles, so a retired mobile endpoint cannot survive in a newer desktop's
`skip-proxy` or `tun-excluded-routes`. Current server exclusions are then derived
from the shared inventory. Existing inventories require a scoped cleanup of any
previously retained retired endpoint; do not recreate them over local edits.

Set `campus.confirmed_on_campus` only for an actual campus egress and configure
`campus.dns` with verified resolver IP addresses. This batch uses PKU's documented
`162.105.129.122` and `162.105.129.88`; availability still needs verification on
the target campus network. Legacy `["system"]` remains supported but depends on
OS DNS state and is not selected for this batch. Add genuine extra license-server prefixes to `extra_cidrs` and
institutional service suffixes to `extra_domains` when necessary.

For subsequent updates, from this repository:

```bash
python3 tools/surge2clash.py
python3 tests/device_profiles_test.py
python3 tools/device_profiles.py build \
  --inventory ../DeviceProfiles/inventory.json --out ../DeviceProfiles/dist
python3 tools/device_profiles.py build --check \
  --inventory ../DeviceProfiles/inventory.json --out ../DeviceProfiles/dist
```

The builder validates all candidates with Surge and Mihomo before replacing
outputs. Mihomo validation uses temporary local providers and real MMDB files;
it does not enable a TUN or start a client. `--check` additionally compares all
generated bytes. Keep `inventory.json` and `dist/` private; new files are mode
0600 and created directories mode 0700. The builder rejects private paths inside
this repository. Native error logs, which may contain sensitive lines, also stay
outside the repository. Public routing changes still need the full
[maintenance validation and release workflow](MAINTENANCE.md#validate-a-change)
before deploying `@main` references. A private profile build does not publish
new public lists. Run this build after future routing changes as well as node
changes, then distribute all affected outputs together.

## Encrypted DNS

`config/device-dns.json` owns the encrypted resolver pools for all five private
profiles. It does not change the public Mihomo merge template. Each pool has
two DoH and two DoT endpoints, all using IP literals to avoid resolver-hostname
bootstrap. Certificate verification stays enabled; no plaintext public fallback
is added.

| Pool | DoH | DoT |
|---|---|---|
| Global / proxy | `https://8.8.8.8/dns-query`, `https://1.1.1.1/dns-query` | `tls://8.8.4.4`, `tls://1.0.0.1` |
| Domestic / direct | `https://223.5.5.5/dns-query`, `https://120.53.53.53/dns-query` | `tls://223.6.6.6`, `tls://1.12.12.12` |

Surge uses the global pool by default and the direct pool for managed DIRECT
domain lists. Its encrypted connections follow routing rules. The local check
confirmed direct routing for the domestic resolver addresses and proxy routing
for the global addresses. Surge queries pool members concurrently and accepts
the first answer; these are not sequential primary/backup servers.
The remaining ordinary `dns-server` entries are for connectivity checks and
encrypted-resolver hostname bootstrap, not a parallel public-query fallback.

Mihomo uses explicit `#Proxy` / `#DIRECT` resolver paths; its bootstrap,
proxy-server and direct resolver pools also include DoT. Both desktop platforms
map `tailscale.com`, `tailscale.io` and `tailscale.net` to the direct encrypted
pool so VPN control DNS does not depend on the proxy path. Native iOS Tailscale
behavior stays separate. MagicDNS still uses Quad100; local and campus DNS
exceptions retain their existing resolvers. Campus `system` DNS is not claimed
to be encrypted. Do not replace it with public DNS without campus evidence.

All eight endpoints returned valid DNS wire responses with certificate
verification on the local Mac on 2026-10-05. Other target networks require their
own runtime checks. See the [Surge encrypted DNS documentation](https://manual.nssurge.com/dns/encrypted-dns.html)
and [Mihomo DNS types](https://wiki.metacubex.one/config/dns/type/).

## Tailscale boundaries

Desktop DNS is owned by Surge/Mihomo. Disable **Use Tailscale DNS settings** on
each desktop with `tailscale set --accept-dns=false`, or the equivalent Tailscale
GUI preference. The generated shell/PowerShell scripts apply only this flag;
they are never run by the builder. Enable the appropriate proxy configuration
first, then run `sh ./tailscale-dns-off.sh` on Mac/Mac mini or
`./tailscale-dns-off.ps1` in Windows PowerShell. If permission or script execution
policy prevents the change, use the Tailscale GUI toggle. Importing a proxy
profile cannot change this independent application preference.

Keep tailnet-wide MagicDNS enabled. Always send the entire `ts.net` namespace
to Quad100: Surge uses `ts.net` and `*.ts.net`, while Mihomo uses `+.ts.net`.
These selectors cover all subdomain depths without enumerating devices or
individual tailnets. `tailscale.magic_domains` can add other dedicated namespaces
but cannot narrow this coverage; redundant `ts.net` descendants are collapsed.
The same suffixes generate resolver mappings on all five profiles, plus real-IP
exceptions and proxy bypass on desktops. iOS retains its native Tailscale
outbound instead of OS bypass. Tailscale documents that Quad100 continues
answering MagicDNS with `accept-dns=false`; the proxy forwards only the private
DNS namespace there. Public DNS uses the proxy's configured resolvers, and campus
queries use campus DNS. Do not add Quad100 to general DNS upstream/fallback lists.
Use fully qualified peer names because the disabled Tailscale DNS configuration
no longer supplies a reliable OS search suffix. Private split-DNS domains beyond
MagicDNS require explicit mappings rather than assuming automatic import.

On macOS, leave `100.64.0.0/10` and explicitly configured IPv4
`tailscale.extra_routes` out of Surge's `tun-excluded-routes`.
Tailscale must own those OS routes. An IPv4 exclusion can install a route through
the physical gateway that wins over Tailscale's same-prefix tunnel route; this
caused IPv4 SSH timeouts on the local Mac on 2026-10-05. The builder removes
these IPv4 exclusions from inherited bases while preserving unrelated exclusions
and non-Tailscale proxy-server bypasses. Retain the existing IPv6 exclusions,
including `fd7a:115c:a1e0::/48`: removing that exclusion in the same live check
removed the usable Tailscale IPv6 route and sent peer traffic into Surge's default
route.
Verify both families on each target; their exclusion behavior differs.
The later DNS review on the same date found no usable IPv6 route to an actual
online peer (`No route to host`), while IPv4 SSH succeeded. The exclusion setting
was unchanged in that review; do not treat the earlier IPv6 result as current
verification or add guessed physical-gateway routes to compensate.
Windows retains its separate Mihomo
`route-exclude-address` configuration; this Mac observation does not establish
a Windows routing fault. MagicDNS uses Quad100 and real-IP DNS;
control/relay domains use DIRECT. Surge explicitly retains `hijack-dns = *:53`
from the imported design; removing it during generation allowed captured
hardcoded DNS queries to avoid the internal resolver. On the local Mac,
Quad100 has its own route through the Tailscale interface. Verify that route
and MagicDNS resolution on each target rather than disabling general DNS
capture to protect a single upstream. Windows disables
`strict-route` because its DNS firewall can interfere with the separate VPN's
DNS. This is an interoperability choice, not proof of universal DNS interception
or leak prevention. IPv6 and endpoint routes must be checked on each device.

## DNS capture and complete bypass

Keep the three stages separate: capture DNS, choose its upstream, then route
application traffic. Surge `[Host]` mappings use exact names, `*`/`?` wildcards,
and domain entries from `RULE-SET` / `DOMAIN-SET`, with the first match winning.
These are not arbitrary regular expressions. The existing ordered list mappings
remain the source for public resolver selection; scoped private and campus
mappings take precedence. An IP rule cannot select a resolver before resolution.

`hijack-dns = *:53` does not establish universal DNS control. On 2026-10-05,
local UDP queries to `8.8.8.8:53` received Surge fake addresses, while a TCP query
to the same endpoint received public real addresses. This is evidence of a
capture gap, not evidence about that TCP query's outbound policy. OS-routed
bypass networks, IPv6 DNS and application-managed DoH/DoT need separate checks.
Mihomo configures both `any:53` and `tcp://any:53`; target-device verification is
still required, especially with Windows strict routing disabled.

For complete application-traffic bypass on Surge, pair `skip-proxy` host/IP
selectors with `tun-excluded-routes` **CIDRs**. A hostname additionally needs
`always-real-ip`, and its returned addresses must actually use bypass routes.
`DIRECT` still traverses Surge. `skip-proxy` alone does not exclude a connection
from the VIF, and an IP-only system-proxy exception does not match a request
made by hostname. The current local Mac has system proxy disabled, so only
the OS route path applies to applications without an explicit proxy.

Never copy the whole `PrivateLANIP` list into TUN exclusions: it contains the
Surge fake-IP pool `198.18.0.0/15`, and broad ULA space overlaps Surge's IPv6
listener. Arbitrary public domain categories can resolve to shared or changing
CDN addresses; a static CIDR exclusion is not a domain-scoped bypass guarantee.
Test actual route/interface behavior before deployment. Campus profiles pair
PKU and explicit extra-domain real-IP exceptions with PKUIP/extra-CIDR exclusions;
publisher and software DIRECT overlays do not receive arbitrary CDN exclusions.
Queries addressed directly to an OS-bypassed DNS endpoint can themselves bypass
capture; normal system DNS queries enter Surge/Mihomo first, and only the
resolver's upstream exchange then follows that dedicated route.

Private desktop transport exceptions may name only `tailscaled`, the two official
macOS Tailscale network-extension process names, or Windows `tailscaled.exe`.
The private inventory must record `process_exception_reason`. The builder rejects
other processes. These narrowly scoped exceptions prevent the VPN transport from
being proxied back into another tunnel; they do not relax the prohibition on
process rules in public source lists. On macOS a Tailscale subnet/exit router may
reconstruct application connections in that same process: those connections then
also use DIRECT. This is suitable for the campus egress requested here, but does
not make Tailscale exit-node traffic traverse Surge's entire public rule tree.

iOS instead retains the original native Tailscale policy and section name, routes
tailnet addresses to that policy, and removes conflicting desktop exclusions.
Interactive login is device-local: a new phone must sign in through the Surge
policy editor. Copying a configuration does not copy login state. Use Surge iOS
5.21 or newer for interactive login. Approved subnet routes can be listed in
`tailscale.extra_routes`; this configuration does not advertise an exit node or
subnet router and does not grant tailnet access.

Proxy server IPs within `TAILNET` or `tailscale.extra_routes` follow these same
boundaries. Mac and gateway profiles omit their IPv4 host-route exclusions and
remove inherited exact IPv4 endpoint IPs/host CIDRs from `tun-excluded-routes`,
while retaining existing IPv6 behavior. iOS removes endpoint IPs/host CIDRs from
both bypass lists and adds `underlying-proxy` using the unique `ios_tailscale`
policy name. This is an iOS rendering change, not an inventory mutation. Existing shared
Surge dialers on these endpoints are rejected rather than overwritten; native
policy names must not collide with nodes, groups or built-in policies. Ordinary
proxy definitions and group options remain unchanged.

## Campus behavior

The campus variants assume their physical internet egress is the campus network.
They route PKU services, academic publishers, and the reviewed software families
DIRECT. The optional domain overlay is placed after Reject and before ordinary
service proxies, so an earlier proxy rule cannot remove the campus identity.
Raw campus address rules use `no-resolve`; they never initiate DNS before the
domain stage. Both campus variants exclude those campus prefixes from TUN
capture. Mac mini also adds the corresponding IPs and domain patterns to
`skip-proxy`; both variants return real IPs for PKU and explicit extra domains.
Exclusions overlapping Tailscale routes or proxy listener/fake-IP ranges fail
generation. Public publisher/CDN addresses are not added to these exclusions.
These are deliberate device-scoped exceptions, not global rule ownership moves.

The two campus variants use the same suffixes, campus IP source list, and DNS
selection. Account, content, and known asset families remain on that campus exit.
SPSS and other campus license servers inside the PKU address ranges are covered
even when an application uses a literal IP. This does not authorize changing
Microsoft/OneDrive or all Adobe/IBM traffic to DIRECT; school-hosted activation
and SSO endpoints are already covered by PKU. Additional external license hosts
require actual service evidence. Some licenses require a university account or
explicit entitlement independently of source IP.

Campus DHCP DNS must remain available on the physical interface. Do not set the
gateway host's own upstream DNS or default gateway to its Surge fake-IP listener
or its VM Gateway address. Explicit campus upstreams avoid inheriting DNS changes
from another VPN. School access from outside campus is a different
configuration requiring an approved campus VPN, CARSI, or an authorized campus
exit; DIRECT alone does not supply that exit.

## Manual deployment

Import the appropriate complete configuration on each device. Review application
modules/overrides because they can supersede imported DNS, routes, and TUN values.
In Clash Verge Rev turn **System Proxy off**, **TUN on**, and **Strict Route off**.
Merge the two fields in `verge-settings.merge.yaml` into the application's
preferences only; never replace the whole application preferences with that
fragment. Verify the final running TUN exclusions, since saved TUN dialog fields
can override the imported YAML. Keep DNS override off so the profile's split DNS
is retained. Existing group-selection caches can override initial member order.

On Mac mini, enable the intended Surge VM Gateway mode in the application and
point LAN clients at its actual gateway/DNS addresses. VM network addressing,
DHCP, IPv6 RA, Tailscale route advertisements and grants are runtime/target
machine settings; a copied Surge profile cannot provision them. Disable UDP Fast
Path for gateway clients whose traffic must follow Surge routing. Tailnet access
from LAN clients also needs valid OS routes and forwarding on that gateway.

Verify on the target devices: peer IP and MagicDNS access; campus portal and
license-server connectivity; publisher institutional recognition; IPv4 and IPv6;
and client behavior after reboot. Syntax and offline rule tests do not prove
authenticated licenses, campus egress, or gateway forwarding.
